Эти документы представляют собой машинный перевод текста публичного проекта и не все были проверены носителями языка. Обратитесь к английскому или китайскому источнику для устранения технической двусмысленности. Никакие личные данные пользователя не включены.

Разверните исходный пакет Local AI Studio на этой новой машине. Перенести существующий источник; не перестраивайте аналогичный сайт с нуля.

1. Прочтите README-FIRST.en.txt и источник. Проверьте ОС, архитектуру, память, свободный диск, графический процессор и установленные инструменты. Сообщите о совместимости. Apple Silicon — проверенная платформа; определить работу по адаптации для других платформ вместо того, чтобы требовать прямой поддержки.
2. Используйте ~/Library/Application Support/LocalImageStudio: app для источника, runtime для environments/engines/tasks, models для весов. Установите app/.local -> ../runtime и runtime/image-models -> ../models.. Избегайте iCloud Desktop/Documents.. Не используйте повторно старые имена пользователей, IP-адреса или идентификаторы Tailnet.
3. Установите необходимые стабильные инструменты: Python 3.11, Node (исходный компьютер использовал 25), CMake, инструменты сборки и LM Studio. Используйте изолированные среды и устанавливайте зависимости image/video отдельно от requirements/viggle-pinned.txt и src/h3_requirements.lock.. Если версия недоступна или несовместима, сообщите об ошибке вместо автоматического обновления. Адаптация Apple H3/ClipProj является экспериментальной.
4. Разверните vendor/stable-diffusion.cpp и vendor/ggml-source в runtime. Исходный код уже содержит изменения; не применяйте исторические патчи дважды. Используйте конфигурацию CMake: -DSD_METAL=ON -DSD_WEBP=OFF -DSD_WEBM=OFF -DSD_GGML_SOURCE_DIR=<absolute ggml path> -DCMAKE_BUILD_TYPE=Release. Создайте sd-cli и другие цели, требуемые кодом.
5. Загрузите закрепленные версии, используя манифесты модели JSON и установщики под src/.. Поддержка возобновления и проверки sizes/SHA256.. Получение доверенных восходящих хэшей там, где они отсутствуют, и их запись; никогда не изобретайте хеши. Выберите работоспособные модули в соответствии с емкостью memory/disk; не заменяйте молча models. Установите текстовую модель, указанную в README, в LM Studio с псевдонимом, используемым в коде, локальным портом API 1234. Не копируйте старую конфигурацию учетной записи.
6. Установите видео отдельно в video-experimental: ComfyUI из https://github.com/comfyanonymous/ComfyUI и ClipProj из https://github.com/nicolab28/ComfyUI-ClipProj. Закрепите коммиты, записанные под patches/, и примените каждый deployed.patch один раз. Загрузите и проверьте активы h3_apple_models.json. Сохраните защиту памяти. Не применяйте также src/h3_apple_*.patch. Проверьте поддерживаемые текущим кодом комбинации resolution/frame/audio; не расширяйте непроверенные возможности.
7. Проверяйте жестко закодированные пути /Users/, переменные среды, каталоги моделей и исполняемые файлы на целевом компьютере. Сохраняйте /edit, /chat, /video, задачу IDs/queues/progress, подтверждение удаления, задачи фонового чата и ссылки. Не импортируйте старые изображения chats/tasks/reference. Сохраните селектор 中文/Английский и языковые предпочтения.
8. Запустите node app/src/image_gallery.mjs по шлейфу со средой, определенной исходным кодом. Проверьте готовность HTTP и модели. Избегайте конфликтов на портах 1235 (веб), 1234 (текстовый API), 8191 (видеосервер). Настраивайте LAN/private Tailscale только по запросу; не включайте публичный Funnel. Прочитайте адрес нового устройства вместо повторного использования старого адреса.
9. Запустите соответствующие изолированные тесты. Благодаря недавно написанным неконфиденциальным подсказкам проверяйте полные ответы чата, stop/reconnect после обновления, вывод реального изображения с визуальным осмотром и воспроизводимое короткое видео. Запись time/dimensions/memory. HTTP 200 или наличие файла само по себе не является принятием.
10. Настройте запуск после входа в систему локального пользователя, отображаемое имя Local AI Studio. Если запрашивается операция предварительного входа в систему, сначала проверьте ограничения OS/FileVault. Логин LaunchAgent без логина не запускается.
11. Сохраните инструкции по локальному развертыванию, команды start/stop, версии paths/model/dependency и результаты проверки. Не читайте несвязанные личные файлы. Разрешить пользователю вводить пароли администратора или логины учетной записи; продолжить другие авторизованные работы по установке. Сообщайте об остальных блокировщиках и никогда не заявляйте о пройденных невыполненных проверках.
12. Аутентификация веб-сайта включена по умолчанию. Попросите пользователя создать первого администратора в локальном каталоге /setup, а затем протестировать проверенные бизнес-API. Ожидается неаутентифицированный /api/models, возвращающий 401. Не отключайте аутентификацию и не копируйте старую базу данных учетных записей. См. docs/accounts.en.md..
