# аккаунтов на сайте

## Использование

На Mac, на котором запущена служба, откройте `http://127.0.0.1:1235/setup`, чтобы создать первого администратора. Имена пользователей содержат буквы 3–32, цифры, символы подчеркивания или дефисы и преобразуются в нижний регистр. Пароли содержат символы 12–128. Учетных данных по умолчанию нет. Удаленные устройства не могут претендовать на исходную учетную запись администратора.

После настройки устройства, не прошедшие проверку подлинности, увидят страницу входа. Откройте **Аккаунт/Выход** (`/account`), чтобы изменить пароль или выйти из системы. Администраторы могут создавать users/administrators, сбрасывать пароли, учетные записи disable/enable, изменять роли и удалять учетные записи. Удаление и изменение разрешений требуют подтверждения. Сервер предотвращает удаление, отключение или понижение в должности последнего включенного администратора. Удаление учетной записи не удаляет общие задачи.

Используйте языковое меню в правом верхнем углу, чтобы выбрать один из языков 33. Браузер запоминает ваш выбор. Языковые пакеты обслуживаются локально; при переключении языков контент не отправляется в службу онлайн-перевода. Подсказки пользователя, разговоры и сохраненный контент сохраняют исходный язык.

Это общая студия. Вошедшие в систему пользователи имеют общий доступ к изображениям, видео и задачам чата на стороне сервера. История чата в браузере сохраняется в localStorage. Нет мультитенантной изоляции, хранения задач по каждому пользователю или выставления счетов. Существующее ограничение на использование только локального видео остается.

## Хранение и защита

- `src/studio_auth.mjs` запускается перед бизнес-маршрутами, включая API и файлы image/reference/video. Неаутентифицированные страницы перенаправляются с помощью 303; API и медиа возвращают 401. Ресурсы учетной записи, языковые ресурсы и несекретный статус setup/sign-in являются общедоступными.
- Файл аккаунта: `LOCAL_IMAGE_DATA_DIR/auth/users.json`, по умолчанию `app/.local/auth/users.json`; выделенное развертывание использует `runtime/auth/users.json`. Режим каталога: 0700; режим файла: 0600. В паролях используются scrypt N32768/r8/p1, случайные соли и сравнение хэшей в постоянное время. Записи являются атомарными, а изменения учетной записи сериализуются. Поврежденная существующая база данных препятствует запуску, а не возобновляет регистрацию.
- В сессиях используются случайные байты 32; сервер хранит только дайджест. Файлы cookie: HttpOnly, SameSite=Strict, действительны в течение 12 часов. Для перезапуска требуется повторный вход. Password/role изменения, сброс, отключение и удаление отменяют затронутые сеансы. Выход из системы не удаляет и не запускает повторно уже начатые задачи.
- Для записи требуются Origin и JSON одного происхождения. X-Forwarded-For не заслуживает доверия. Каждый IP-адрес источника получает не более попыток 15 sign-in/setup/self-password-change за 15 минут. Ограничения: одновременное создание паролей 4 и учетные записи 100. При перезапуске лимиты попыток очищаются.
— Существующее развертывание использует HTTP через частный Tailscale. Tailscale шифрует передачу данных между устройствами; обычный LAN HTTP сам по себе этого не делает. Публичный доступ и TLS не настраиваются в этом пакете. Файлы cookie Secure устанавливаются только для собственных запросов TLS. Не раскрывайте его напрямую через общедоступный HTTP.
- Никогда не загружайте базу данных аутентификации, сеансы или пароли. Инициализируйте новые учетные записи при миграции. stdio MCP, локальные разрешения LM Studio и файлы ОС находятся за пределами аутентификации веб-сайта.

## Проверка

Запустите `node tests/studio_auth.mjs` с его временной базой данных учетных записей и без настоящего models. Он охватывает блокировку API/media без аутентификации, ограничения источника исходной настройки, роли, режимы пароля hashing/file, защиту последнего администратора, отзыв сеанса, сохранение, отклонение поврежденных файлов и ограничения скорости.

Тесты local_chat,chat_background, image_studio и video_web входят в систему с помощью изолированных администраторов тестирования; обхода аутентификации производства нет. Реальные пароли вводятся пользователем и не должны сохраняться в тестах или документации.
