Dokumenty te są tłumaczeniami maszynowymi tekstów projektów publicznych i nie wszystkie zostały sprawdzone przez rodzimych użytkowników języka. W przypadku niejasności technicznych należy zapoznać się ze źródłem angielskim lub chińskim. Żadne prywatne dane użytkownika nie są uwzględniane.

Wdróż pakiet źródłowy Local AI Studio na tej nowej maszynie. Przeprowadź migrację istniejącego źródła; nie buduj podobnej witryny od zera.

1. Przeczytaj README-FIRST.en.txt i źródło. Sprawdź system operacyjny, architekturę, pamięć, wolny dysk, procesor graficzny i zainstalowane narzędzia. Zgłoś zgodność. Apple Silicon to sprawdzona platforma; zidentyfikować prace adaptacyjne dla innych platform, zamiast ubiegać się o bezpośrednie wsparcie.
2. Użyj ~/Library/Application Support/LocalImageStudio: app dla źródła, runtime dla environments/engines/tasks, models dla ciężarów. Ustaw app/.local -> ../runtime i runtime/image-models -> ../models. Unikaj iCloud Desktop/Documents. Nie używaj ponownie starych nazw użytkowników, adresów IP ani tożsamości Tailnet.
3. Zainstaluj wymagane stabilne narzędzia: Python 3.11, Node (używana maszyna źródłowa 25), CMake, narzędzia do kompilacji i LM Studio. Używaj izolowanych środowisk i instaluj zależności image/video oddzielnie od requirements/viggle-pinned.txt i src/h3_requirements.lock.. Jeśli wersja jest niedostępna lub niekompatybilna, zgłoś błąd zamiast cichej aktualizacji. Adaptacja H3/ClipProj Apple jest eksperymentalna.
4. Wdróż vendor/stable-diffusion.cpp i vendor/ggml-source w runtime. Źródło zawiera już zmiany; nie stosuj łatek historycznych dwukrotnie. Użyj konfiguracji CMake: -DSD_METAL=ON -DSD_WEBP=OFF -DSD_WEBM=OFF -DSD_GGML_SOURCE_DIR=<absolute ścieżka ggml> -DCMAKE_BUILD_TYPE=Release. Kompiluj sd-cli i inne cele wymagane przez kod.
5. Pobierz przypięte wersje przy użyciu manifestów modelu JSON i instalatorów w obszarze src/. Wznów wsparcie i zweryfikuj sizes/SHA256. Uzyskaj zaufane skróty nadrzędne tam, gdzie ich brakuje i zapisz je; nigdy nie wymyślaj skrótów. Wybierz moduły, które można uruchomić, zgodnie z wydajnością memory/disk; nie zastępuj po cichu models. Zainstaluj model tekstowy określony w pliku README w LM Studio z aliasem używanym przez kod, lokalnym portem API 1234. Nie kopiuj starej konfiguracji konta.
6. Zainstaluj wideo oddzielnie w video-experimental: ComfyUI z https://github.com/comfyanonymous/ComfyUI i ClipProj z https://github.com/nicolab28/ComfyUI-ClipProj. Przypnij zatwierdzenia zapisane w patches/ i zastosuj każde deployed.patch raz. Pobierz i zweryfikuj zasoby h3_apple_models.json. Zachowaj ochronę pamięci. Nie nakładać również poprawki src/h3_apple_*. Sprawdź obsługiwane kombinacje resolution/frame/audio bieżącego kodu; nie rozszerzaj niezatwierdzonych możliwości.
7. Przeprowadź inspekcję zakodowanych na stałe ścieżek /Users/, zmiennych środowiskowych, katalogów modeli i plików wykonywalnych dla maszyny docelowej. Zachowaj /edit, /chat, /video, zadanie IDs/queues/progress, potwierdzenie usunięcia, zadania czatu w tle i referencje. Nie importuj starych obrazów chats/tasks/reference. Zachowaj selektor 中文 / angielski i preferencje językowe.
8. Uruchom node app/src/image_gallery.mjs w pętli zwrotnej w środowisku zdefiniowanym przez źródło. Sprawdź gotowość protokołu HTTP i modelu. Unikaj konfliktów na portach 1235 (internet), 1234 (tekstowe API), 8191 (backend wideo). Skonfiguruj LAN/private Tailscale tylko na żądanie; nie włączaj publicznego Funnel. Przeczytaj adres nowego urządzenia zamiast ponownie używać starego adresu.
9. Przeprowadź odpowiednie izolowane testy. Dzięki nowo napisanym, niewrażliwym podpowiedziom, możesz zweryfikować pełne odpowiedzi na czacie, stop/reconnect po odświeżeniu, uzyskać rzeczywisty obraz z kontrolą wizualną i krótkim filmem do odtworzenia. Nagranie time/dimensions/memory. HTTP 200 lub samo istnienie pliku nie jest akceptowane.
10. Skonfiguruj uruchamianie po zalogowaniu użytkownika lokalnego, nazwa wyświetlana Local AI Studio. Jeśli zażądano operacji przed zalogowaniem, najpierw sprawdź ograniczenia OS/FileVault. Login LaunchAgent nie uruchamia się bez logowania.
11. Zapisz lokalne instrukcje wdrażania, polecenia start/stop, wersje paths/model/dependency i wyniki walidacji. Nie czytaj niepowiązanych plików prywatnych. Pozwól użytkownikowi wprowadzić hasła administratora lub loginy do konta; kontynuować inne autoryzowane prace instalacyjne. Podaj pozostałe blokery i nigdy nie mów, że niewykonane kontrole zostały pomyślnie zakończone.
12. Uwierzytelnianie witryn internetowych jest domyślnie włączone. Poproś użytkownika o utworzenie pierwszego administratora w katalogu lokalnym /setup, a następnie przetestuj uwierzytelnione biznesowe interfejsy API. Oczekiwany jest nieuwierzytelniony zwrot /api/models 401. Nie wyłączaj uwierzytelniania ani nie kopiuj starej bazy danych kont. Zobacz docs/accounts.en.md.
