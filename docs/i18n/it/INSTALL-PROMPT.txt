Distribuisci il pacchetto sorgente Local AI Studio su questa nuova macchina. Migrare la fonte esistente; non ricostruire un sito web simile da zero.

1. Leggi README-FIRST.en.txt e la fonte. Ispeziona sistema operativo, architettura, memoria, disco libero, GPU e strumenti installati. Segnala compatibilità. Apple Silicon è la piattaforma validata; identificare il lavoro di adattamento per altre piattaforme invece di richiedere un sostegno diretto.
2. Utilizzare ~/Library/Application Support/LocalImageStudio: app per la sorgente, runtime per environments/engines/tasks, models per i pesi. Imposta app/.local -> ../runtime e runtime/image-models -> ../models. Evita iCloud Desktop/Documents. Non riutilizzare vecchi nomi utente, IP o identità Tailnet.
3. Installa gli strumenti stabili richiesti: Python 3.11, Node (la macchina di origine utilizzava 25), CMake, strumenti di creazione e LM Studio. Utilizza ambienti isolati e installa le dipendenze image/video separatamente da requirements/viggle-pinned.txt e src/h3_requirements.lock. Se una versione non è disponibile o non è compatibile, segnala l'errore invece di eseguire l'aggiornamento in modalità silenziosa. L'adattamento Apple H3/ClipProj è sperimentale.
4. Distribuisci vendor/stable-diffusion.cpp e vendor/ggml-source in runtime. La fonte include già le modifiche; non applicare le patch storiche due volte. Utilizza la configurazione CMake: -DSD_METAL=ON -DSD_WEBP=OFF -DSD_WEBM=OFF -DSD_GGML_SOURCE_DIR=<absolute percorso ggml> -DCMAKE_BUILD_TYPE=Release. Costruisci sd-cli e altri target richiesti dal codice.
5. Scarica le revisioni aggiunte utilizzando i manifest e i programmi di installazione del modello JSON in src/. Riprendi il supporto e verifica sizes/SHA256. Ottieni hash upstream affidabili laddove mancanti e registrali; non inventare mai gli hash. Selezionare i moduli eseguibili in base alla capacità memory/disk; non sostituire silenziosamente models. Installa il modello di testo specificato dal README in LM Studio con l'alias utilizzato dal codice, porta API locale 1234. Non copiare la configurazione del vecchio account.
6. Installa il video separatamente in video-experimental: ComfyUI da https://github.com/comfyanonymous/ComfyUI e ClipProj da https://github.com/nicolab28/ComfyUI-ClipProj. Blocca i commit registrati in patches/ e applica ciascuno deployed.patch una volta. Scarica e verifica le risorse h3_apple_models.json. Preserva la protezione della memoria. Non applicare anche src/h3_apple_*.patch. Controlla le combinazioni resolution/frame/audio supportate dal codice corrente; non espandere le capacità non convalidate.
7. Controlla i percorsi /Users/ codificati, le variabili di ambiente, le directory dei modelli e gli eseguibili per il computer di destinazione. Conserva /modifica, /chat, /video, attività IDs/queues/progress, conferma dell'eliminazione, attività di chat in background e riferimenti. Non importare vecchie immagini chats/tasks/reference. Conserva il selettore 中文/inglese e la preferenza della lingua.
8. Avvia node app/src/image_gallery.mjs in loopback con l'ambiente definito dall'origine. Verificare la disponibilità del modello e dell'HTTP. Evita conflitti sulle porte 1235 (web), 1234 (API di testo), 8191 (backend video). Configurare LAN/private Tailscale solo se richiesto; non abilitare Funnel pubblico. Leggi l'indirizzo del nuovo dispositivo invece di riutilizzare un vecchio indirizzo.
9. Eseguire test isolati pertinenti. Con istruzioni non sensibili appena scritte, verifica le risposte complete della chat, stop/reconnect dopo l'aggiornamento, output di immagini reali con ispezione visiva e breve video riproducibile. La registrazione time/dimensions/memory. HTTP 200 o la sola esistenza del file non costituiscono accettazione.
10. Configura l'avvio dopo l'accesso dell'utente locale, nome visualizzato Local AI Studio. Se è richiesta l'operazione di pre-accesso, controllare prima i vincoli OS/FileVault. Un login LaunchAgent non viene avviato senza login.
11. Salva le istruzioni di distribuzione locale, i comandi start/stop, le versioni paths/model/dependency e i risultati della convalida. Non leggere file privati ​​non correlati. Consentire all'utente di inserire password di amministratore o accessi all'account; continuare altri lavori di installazione autorizzati. Indica i restanti bloccanti e non rivendicare mai il superamento dei controlli non eseguiti.
12. L'autenticazione del sito Web è abilitata per impostazione predefinita. Chiedi all'utente di creare il primo amministratore in locale /setup, quindi testare le API aziendali autenticate. È prevista la restituzione di /api/models non autenticato 401. Non disabilitare l'autenticazione né copiare un vecchio database di account. Vedi docs/accounts.en.md.
