Ces documents sont des traductions automatiques de textes publics de projets et n'ont pas tous été révisés par des locuteurs natifs. Consultez la source anglaise ou chinoise en cas d'ambiguïté technique. Aucune donnée utilisateur privée n'est incluse.

Déployez le package source Local AI Studio sur cette nouvelle machine. Migrer la source existante ; ne reconstruisez pas un site Web similaire à partir de zéro.

1. Lisez README-FIRST.en.txt et la source. Inspectez le système d’exploitation, l’architecture, la mémoire, le disque libre, le GPU et les outils installés. Compatibilité du rapport. Apple Silicon est la plateforme validée ; identifier le travail d’adaptation pour d’autres plateformes au lieu de réclamer un soutien direct.
2. Utilisez ~/Library/Application Support/LocalImageStudio : app pour la source, runtime pour environments/engines/tasks, models pour les poids. Définissez app/.local -> ../runtime et runtime/image-models -> ../models. Évitez iCloud Desktop/Documents. Ne réutilisez pas les anciens noms d'utilisateur, adresses IP ou identités Tailnet.
3. Installez les outils stables requis : Python 3.11, Node (la machine source utilisait 25), CMake, les outils de construction et LM Studio. Utilisez des environnements isolés et installez les dépendances image/video séparément de requirements/viggle-pinned.txt et src/h3_requirements.lock.. Si une version est indisponible ou incompatible, signalez l'échec au lieu de procéder à une mise à niveau silencieuse. L'adaptation Apple H3/ClipProj est expérimentale.
4. Déployez vendor/stable-diffusion.cpp et vendor/ggml-source dans runtime. La source inclut déjà les modifications ; n'appliquez pas les correctifs historiques deux fois. Utilisez la configuration CMake : -DSD_METAL=ON -DSD_WEBP=OFF -DSD_WEBM=OFF Chemin ggml -DSD_GGML_SOURCE_DIR=<absolute> -DCMAKE_BUILD_TYPE=Release. Construisez sd-cli et les autres cibles requises par le code.
5. Téléchargez les révisions épinglées à l'aide des manifestes et des programmes d'installation du modèle JSON sous src/.. Reprise du support et vérification de sizes/SHA256.. Obtenez les hachages en amont fiables là où ils sont manquants et enregistrez-les ; n'inventez jamais de hachages. Sélectionnez les modules exécutables en fonction de la capacité du memory/disk ; ne remplacez pas silencieusement models. Installez le modèle de texte spécifié par README dans LM Studio avec l'alias utilisé par le code, le port API local 1234. Ne copiez pas l'ancienne configuration du compte.
6. Installez la vidéo séparément dans video-experimental : ComfyUI de https://github.com/comfyanonymous/ComfyUI et ClipProj de https://github.com/nicolab28/ComfyUI-ClipProj. Épinglez les commits enregistrés sous patches/ et appliquez chaque deployed.patch une fois. Téléchargez et vérifiez les actifs h3_apple_models.json. Préserver la protection de la mémoire. N'appliquez pas également src/h3_apple_*.patch. Vérifiez les combinaisons resolution/frame/audio prises en charge par le code actuel ; n’étendez pas les capacités non validées.
7. Auditez les chemins /Users/ codés en dur, les variables d'environnement, les répertoires de modèles et les exécutables de la machine cible. Conservez /edit, /chat, /video, la tâche IDs/queues/progress, la confirmation de suppression, les tâches de discussion en arrière-plan et les références. N'importez pas d'anciennes images chats/tasks/reference. Conservez le sélecteur 中文 / Anglais et la préférence de langue.
8. Démarrez node app/src/image_gallery.mjs en bouclage avec l'environnement défini par la source. Vérifiez la préparation du HTTP et du modèle. Évitez les conflits sur les ports 1235 (web), 1234 (API texte), 8191 (backend vidéo). Configurez LAN/private Tailscale uniquement sur demande ; n'activez pas le Funnel public. Lisez l'adresse du nouvel appareil au lieu de réutiliser une ancienne adresse.
9. Exécutez des tests isolés pertinents. Avec des invites non sensibles nouvellement écrites, vérifiez les réponses complètes du chat, stop/reconnect après actualisation, sortie d'image réelle avec inspection visuelle et courte vidéo lisible. L'enregistrement time/dimensions/memory. HTTP 200 ou l'existence du fichier à lui seul ne constitue pas une acceptation.
10. Configurez le démarrage après la connexion de l'utilisateur local, nom d'affichage Local AI Studio. Si une opération de pré-connexion est demandée, vérifiez d'abord les contraintes OS/FileVault. Une connexion LaunchAgent ne démarre pas sans connexion.
11. Enregistrez les instructions de déploiement local, les commandes start/stop, les versions paths/model/dependency et les résultats de validation. Ne lisez pas les fichiers privés sans rapport. Laissez l'utilisateur saisir les mots de passe d'administrateur ou les identifiants de compte ; poursuivre les autres travaux d'installation autorisés. Indiquez les bloqueurs restants et ne prétendez jamais que les contrôles non effectués ont été réussis.
12. L'authentification du site Web est activée par défaut. Demandez à l'utilisateur de créer le premier administrateur dans /setup local, puis de tester les API métier authentifiées. Un /api/models non authentifié renvoyant 401 est attendu. Ne désactivez pas l'authentification et ne copiez pas une ancienne base de données de comptes. Voir docs/accounts.en.md.
