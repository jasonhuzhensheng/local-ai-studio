Bei diesen Dokumenten handelt es sich um maschinelle Übersetzungen öffentlicher Projekttexte, die nicht alle von Muttersprachlern überprüft wurden. Konsultieren Sie bei technischen Unklarheiten die englische oder chinesische Quelle. Es sind keine privaten Benutzerdaten enthalten.

Stellen Sie das Local AI Studio-Quellpaket auf dieser neuen Maschine bereit. Migrieren Sie die vorhandene Quelle. Erstellen Sie eine ähnliche Website nicht von Grund auf neu.

1. Lesen Sie README-FIRST.en.txt und die Quelle. Überprüfen Sie Betriebssystem, Architektur, Speicher, freie Festplatte, GPU und installierte Tools. Kompatibilität melden. Apple Silicon ist die validierte Plattform; Identifizieren Sie Anpassungsarbeiten für andere Plattformen, anstatt direkte Unterstützung zu beanspruchen.
2. Verwenden Sie ~/Library/Application Support/LocalImageStudio: app als Quelle, runtime für environments/engines/tasks, models für Gewichte. Stellen Sie app/.local -> ../runtime und runtime/image-models -> ../models. ein. Vermeiden Sie iCloud Desktop/Documents.. Verwenden Sie keine alten Benutzernamen, IPs oder Tailnet-Identitäten wieder.
3. Installieren Sie die erforderlichen stabilen Tools: Python 3.11, Node (die Quellmaschine verwendet 25), CMake, Build-Tools und LM Studio. Verwenden Sie isolierte Umgebungen und installieren Sie image/video-Abhängigkeiten getrennt von requirements/viggle-pinned.txt und src/h3_requirements.lock.. Wenn eine Version nicht verfügbar oder inkompatibel ist, melden Sie einen Fehler, anstatt ein stillschweigendes Upgrade durchzuführen. Die Apple-Anpassung H3/ClipProj ist experimentell.
4. Stellen Sie vendor/stable-diffusion.cpp und vendor/ggml-source in runtime bereit. Die Quelle enthält bereits Änderungen; Wenden Sie historische Patches nicht zweimal an. Verwenden Sie die CMake-Konfiguration: -DSD_METAL=ON -DSD_WEBP=OFF -DSD_WEBM=OFF -DSD_GGML_SOURCE_DIR=<absolute ggml-Pfad> -DCMAKE_BUILD_TYPE=Release. Erstellen Sie sd-cli und andere vom Code benötigte Ziele.
5. Laden Sie angeheftete Revisionen mit den Modell-JSON-Manifesten und Installationsprogrammen unter src/. herunter. Support-Fortsetzung und Überprüfung von sizes/SHA256.. Erhalten Sie vertrauenswürdige Upstream-Hashes, wo sie fehlen, und zeichnen Sie diese auf. Erfinde niemals Hashes. Wählen Sie ausführbare Module entsprechend der memory/disk-Kapazität aus. Ersetzen Sie models nicht stillschweigend. Installieren Sie das in der README-Datei angegebene Textmodell in LM Studio mit dem vom Code verwendeten Alias, dem lokalen API-Port 1234. Kopieren Sie nicht die alte Kontokonfiguration.
6. Installieren Sie das Video separat in video-experimental: ComfyUI von https://github.com/comfyanonymous/ComfyUI und ClipProj von https://github.com/nicolab28/ComfyUI-ClipProj.. Pinnen Sie die unter patches/ aufgezeichneten Commits und wenden Sie jeden deployed.patch einmal an. Laden Sie h3_apple_models.json-Assets herunter und überprüfen Sie sie. Speicherschutz beibehalten. Wenden Sie nicht auch src/h3_apple_*.patch an. Überprüfen Sie die vom aktuellen Code unterstützten resolution/frame/audio-Kombinationen. Erweitern Sie nicht validierte Funktionen nicht.
7. Überwachen Sie hartcodierte /Users/-Pfade, Umgebungsvariablen, Modellverzeichnisse und ausführbare Dateien für den Zielcomputer. Behalten Sie /edit, /chat, /video, Aufgabe IDs/queues/progress, Löschbestätigung, Hintergrund-Chat-Aufgaben und Referenzen bei. Importieren Sie keine alten chats/tasks/reference-Bilder. Behalten Sie die Auswahl 中文/Englisch und die Spracheinstellung bei.
8. Starten Sie node app/src/image_gallery.mjs im Loopback mit der von der Quelle definierten Umgebung. Überprüfen Sie die HTTP- und Modellbereitschaft. Vermeiden Sie Konflikte auf den Ports 1235 (Web), 1234 (Text-API), 8191 (Video-Backend). Konfigurieren Sie LAN/private Tailscale nur auf Anfrage. Aktivieren Sie kein öffentliches Funnel. Lesen Sie die Adresse des neuen Geräts, anstatt eine alte Adresse wiederzuverwenden.
9. Führen Sie relevante isolierte Tests durch. Mit neu geschriebenen, nicht sensiblen Eingabeaufforderungen, Überprüfung vollständiger Chat-Antworten, stop/reconnect nach der Aktualisierung, echter Bildausgabe mit visueller Inspektion und abspielbarem Kurzvideo. Record time/dimensions/memory. HTTP 200 oder das Vorhandensein einer Datei allein ist keine Akzeptanz.
10. Konfigurieren Sie den Start nach der lokalen Benutzeranmeldung und zeigen Sie den Namen Local AI Studio an. Wenn ein Voranmeldungsvorgang angefordert wird, prüfen Sie zunächst die OS/FileVault-Einschränkungen. Ein Login LaunchAgent ist kein Start ohne Login.
11. Speichern Sie lokale Bereitstellungsanweisungen, start/stop-Befehle, paths/model/dependency-Versionen und Validierungsergebnisse. Lesen Sie keine unabhängigen privaten Dateien. Lassen Sie den Benutzer Administratorkennwörter oder Kontoanmeldungen eingeben. Führen Sie andere autorisierte Installationsarbeiten fort. Geben Sie die verbleibenden Blocker an und behaupten Sie niemals, dass nicht durchgeführte Schecks bestanden wurden.
12. Die Website-Authentifizierung ist standardmäßig aktiviert. Lassen Sie den Benutzer den ersten Administrator unter lokal /setup erstellen und dann authentifizierte Geschäfts-APIs testen. Es wird erwartet, dass ein nicht authentifizierter /api/models 401 zurückgibt. Deaktivieren Sie nicht die Authentifizierung und kopieren Sie keine alte Kontodatenbank. Siehe docs/accounts.en.md.
