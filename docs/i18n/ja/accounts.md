## 使用法

サービスを実行している Mac で、`http://127.0.0.1:1235/setup` を開いて最初の管理者を作成します。ユーザー名には、3 ～ 32 の文字、数字、アンダースコア、またはハイフンが含まれており、小文字に正規化されます。パスワードには、12 ～ 128 の文字が含まれています。デフォルトの認証情報はありません。リモート デバイスは初期管理者アカウントを要求できません。

セットアップ後、認証されていないデバイスにはサインイン ページが表示されます。 **アカウント / サインアウト** (`/account`) を開いて、パスワードを変更するかサインアウトします。管理者は、users/administrators の作成、パスワードのリセット、disable/enable アカウント、ロールの変更、アカウントの削除を行うことができます。削除と権限の変更には確認が必要です。サーバーは、最後に有効にした管理者の削除、無効化、または降格を防ぎます。アカウントを削除しても、共有タスクは削除されません。

右上の言語メニューを使用して、33 言語から選択します。ブラウザは選択内容を記憶します。言語パックはローカルで提供されます。言語を切り替えても、コンテンツはオンライン翻訳サービスに送信されません。ユーザープロンプト、会話、保存されたコンテンツは元の言語を維持します。

シェアスタジオです。サインインしているユーザーは、画像、ビデオ、サーバー側のチャット タスクへのアクセスを共有します。ブラウザのチャット履歴はlocalStorageに残ります。マルチテナントの分離、ユーザーごとのタスクの保存、または課金はありません。既存のローカルのみのビデオ制限は残ります。

## 保管と保護

- `src/studio_auth.mjs` は、API や image/reference/video ファイルを含むビジネス ルートの前に実行されます。
認証されていないページは 303 でリダイレクトされます。 API とメディアは 401 を返します。
アカウント資産、言語資産、および非秘密の setup/sign-in ステータスは公開されます。
- アカウント ファイル: `LOCAL_IMAGE_DATA_DIR/auth/users.json`、デフォルトは `app/.local/auth/users.json`;専用デプロイメントでは `runtime/auth/users.json` を使用します。
ディレクトリモード: 0700;ファイルモード：0600。
パスワードは、scrypt N32768/r8/p1、ランダム ソルト、定数時間ハッシュ比較を使用します。
書き込みはアトミックであり、アカウントの変更はシリアル化されます。
既存のデータベースが破損していると、登録が再開されず、起動が妨げられます。
- セッションは 32 ランダム バイトを使用します。サーバーにはダイジェストのみが保存されます。
Cookie は HttpOnly、SameSite=Strict で、12 時間有効です。
再起動するには、再度サインインする必要があります。
Password/role の変更、リセット、無効化、削除により、影響を受けるセッションが取り消されます。
サインアウトしても、すでに開始されたタスクは削除されたり、再実行されたりしません。
- 書き込みには同じオリジンの Origin と JSON が必要です。
X-Forwarded-For は信頼されていません。
各送信元 IP は、15 分あたり最大 15 sign-in/setup/self-password-change 回の試行を取得します。
制限: 4 の同時パスワード導出と 100 アカウント。
再起動すると試行制限がクリアされます。
- 既存の展開では、プライベート Tailscale 経由で HTTP を使用します。
Tailscale はデバイス間の転送を暗号化します。通常の LAN HTTP 自体はそうではありません。
パブリック アクセスと TLS は、このパッケージでは構成されません。
Secure Cookie はネイティブ TLS リクエストに対してのみ設定されます。
パブリック HTTP 経由で直接公開しないでください。
- 認証データベース、セッション、パスワードをアップロードしないでください。
移行時に新しいアカウントを初期化します。
stdio MCP、ローカル LM Studio、および OS ファイルのアクセス許可は、Web サイト認証の範囲外です。

## 検証

一時的なアカウント データベースを使用して `node tests/studio_auth.mjs` を実行し、実際の models は使用しません。未認証の API/media ブロック、初期セットアップ元の制限、ロール、パスワード hashing/file モード、最終管理者保護、セッション取り消し、永続性、破損ファイルの拒否、レート制限について説明します。

local_chat、chat_background、image_studio、および video_web テストは、独立したテスト管理者としてサインインします。実稼働認証のバイパスはありません。実際のパスワードはユーザーが入力するものであり、テストやドキュメントに保存してはなりません。
